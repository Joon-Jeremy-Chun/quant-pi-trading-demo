각 과제는 **실행 전 예상 → 실행 → 차이 설명 → 경계값 검사** 순서로 진행합니다. 개인·실거래 자료 대신 합성 값만 사용합니다. 정답 숫자만 적기보다 입력과 계산 과정을 함께 적으세요.

## 과제 1 · 평균과 조건

`build_demo_signal`을 읽고 `[10,10,10]`, `[10,10,13]`, `[13,10,10]`, `[10,10,10,13]`의 결과를 예상합니다. 입력 길이가 정확히 3이면 마지막 3개와 전체가 같다는 점을 생각하세요.

```console
python -c "from src.demo_signal import build_demo_signal; print(build_demo_signal([10,10,10,13]))"
```

제출: 각 입력의 두 평균·문자열 결과, 길이 2와 0 포함 입력의 오류 이유.

## 과제 2 · 같은 값의 다른 처리 시점

`[100,100,100,100,200,50]`, 창 3/5, 가상 초기값 10000을 종이에 적고 다섯 번째 판단과 여섯 번째 처리를 구분하세요. 만약 판단한 200에 즉시 처리했다면 수량이 어떻게 달라졌을까요?

제출: 첫 BUY 날짜, 첫 ENTER 날짜, 처리 가격·가상 수량, 같은 시점 처리와의 차이. [동작 테스트](../tests/test_classroom.py)의 작은 날짜 생성 함수를 참고할 수 있습니다.

## 과제 3 · 미래 자료를 붙이면 과거가 변할까?

과제 2 자료 뒤에 합성 값 세 개를 더 붙입니다. 앞부분의 events는 원래 결과와 같아야 합니다. `final_equity`는 끝 시점이 바뀌므로 같을 필요가 없습니다.

제출: 비교한 두 입력, 같은 범위의 event 비교, 요약 수익률만 비교하면 왜 검증이 안 되는지 설명.

## 과제 4 · 날짜 창의 양 끝

기준일 2026-05-21을 유지하고 창을 0·7·14·22로 바꿉니다. 오늘·끝 날짜를 포함하는지, 음수 창은 어떻게 되는지 확인합니다.

```console
python src/demo_event_alert.py --calendar examples/corporate_events.csv --today 2026-05-21 --lookahead-days 7
```

제출: 각 창에서 선택된 DEMO 식별자와 포함/제외 이유. 달력일과 거래일의 차이는 이 코드가 무엇을 구현했는지 기준으로 설명하세요.

## 과제 5 · 화면의 자료와 동작

JSON의 캐릭터 이름 하나와 task 문장 하나를 바꿉니다. CLI CSV는 수정하지 않습니다. 2D 화면에서 캐릭터 선택 → Next step → Play/Pause → Reset을 확인합니다. 이어 step.agent를 존재하지 않는 id로 바꾸었다가 화면 메시지를 확인하고 원래 값으로 복원합니다.

제출: 바꾼 합성 JSON 항목, 화면 변화, 잘못된 참조의 오류 설명, CSV 출력이 자동으로 바뀌지 않는 이유. [수정 안내](dashboard_3d.ko.md).

## 과제 6 · 자기 검증 하나 작성

평균 경계·날짜 끝 경계·초기 warm-up·보고서 빈 결과 중 하나를 골라 unittest 사례를 추가합니다. 정답이 되는 이유를 먼저 쓰고 assertion을 작성하세요.

```console
python -m unittest discover -s tests -v
```

제출: 테스트 이름, 작은 합성 입력, 독립적으로 계산한 기대값, 실패해야 할 잘못된 구현의 예. 실제 계정이나 외부 서버 연결을 테스트 조건으로 만들지 않습니다.
